# 渠道开发指南（面向 AI Agent / 开发者）

> **本文是新增签到渠道的唯一权威规范。** 无论是我（平台代码）还是后续接手的 Agent，
> 在编写任何新渠道之前必须先通读本文，并严格遵守其中的接口约定与验收清单。

---

## 1. 任务目标

你要为「自动签到管理平台」新增一个**签到渠道**，使得平台能够：

1. 在 Web 界面「渠道管理」页展示该渠道的信息与配置表单；
2. 由用户基于该渠道创建定时任务，按 cron 规则自动执行签到；
3. 捕获脚本的全部输出作为执行日志，并把结构化结果（成功/失败 + 一句话消息）展示在界面上。

## 2. 平台执行模型（30 秒读懂）

平台调用渠道脚本的方式是**子进程执行**，整个过程如下：

```
平台(core/runner.py)
  ├─ 启动子进程:  python -X utf8  channels/<渠道id>/channel.py    (工作目录 = 渠道目录)
  ├─ stdin  : 写入一段 JSON —— 即用户在 Web 界面表单里填写的配置
  ├─ 环境变量: CHECKIN_CONFIG = 配置 JSON 原文
  │            CHECKIN_<KEY大写> = 各配置项的字符串值
  ├─ stdout/stderr: 全部捕获, 存入执行日志(界面上可查看)
  ├─ 超时: 超过任务的"超时时间"后进程被 kill, 记为失败
  └─ 结果: 在脚本输出中查找最后一行 "__CHECKIN_RESULT__{...}" 作为结构化结果
```

**渠道脚本不需要与平台有任何 import 依赖**——它就是一个独立的 Python 脚本，
从 stdin 读配置，正常打印日志，最后输出一行结果 JSON。这保证了渠道与平台解耦、
崩溃互不影响、超时可强杀。

## 3. 目录与文件规范

```
channels/
├── _template/           # 模板目录(平台忽略 _ 开头的目录, 不会加载)
│   ├── channel.py       # ← 新渠道从这里复制
│   └── README.md        # ← 配置获取指南模板
├── example_demo/        # 本地模拟示例(可参考/可删除)
│   ├── channel.py
│   └── README.md
└── <你的渠道id>/        # 例如: workbuddy, tieba, bilibili
    ├── channel.py       # 必须叫这个文件名
    └── README.md        # 人工配置获取指南(见 4.4, 强烈建议提供)
```

规则：

- 目录名即**渠道 id**：只用小写字母、数字、下划线；不以 `_` 或 `.` 开头；与现有渠道不重名。
- 一个渠道一个目录，入口文件**必须**是 `channel.py`。
- 渠道依赖的辅助文件（图片、js 等）也放在同一目录，用相对渠道目录的路径访问
  （平台执行时 `cwd` 就是渠道目录）。
- 若渠道需要第三方库（如 `requests`），加入根目录 `requirements.txt` 并在 META.description 中注明。

## 4. channel.py 必须提供的内容

只有两样东西是平台关心的：**`META` 字典** 和 **`run(config)` 函数**。
文件末尾需要一段固定的引导代码（模板已包含，原样保留即可）。

### 4.1 META —— 渠道元信息与配置表单声明

```python
META = {
    "name": "XX 网每日签到",          # 必填: 界面显示名
    "version": "1.0.0",               # 建议: 语义化版本
    "author": "your-name",            # 可选
    "description": "一句话说明签到目标与规则限制(如积分规则、频率上限)。",  # 建议
    "config_schema": [                # 可选: 声明后 Web 界面自动生成配置表单
        {"key": "cookie", "label": "Cookie", "type": "textarea", "required": True,
         "placeholder": "粘贴完整 Cookie", "help": "浏览器 F12 -> 网络 -> 请求头里复制"},
        {"key": "notify", "label": "签到提醒", "type": "bool", "default": False},
    ],
}
```

`config_schema` 每个字段的属性：

| 属性 | 类型 | 说明 |
|---|---|---|
| `key` | str | 必填。字段名(英文)，`run(config)` 里用这个键取值 |
| `label` | str | 界面显示名称(中文) |
| `type` | str | `text` / `textarea` / `password` / `number` / `bool` / `select`，缺省 `text` |
| `required` | bool | 界面保存时强制校验非空 |
| `default` | any | 默认值(bool 用 False/True，number 用数字) |
| `placeholder` | str | 输入框占位提示 |
| `help` | str | 字段下方的灰色说明文字 |
| `options` | list | 仅 `select` 用: `[{"value": "app", "label": "APP 签到"}, ...]` |

**凭证类内容(Cookie/Token/密码)必须用 `password` 类型**（界面打码显示）；
长文本(Cookie、账号列表)用 `textarea`。

### 4.2 run(config) —— 签到入口

```python
def run(config):
    # config: dict。文本类字段是 str；number 字段平台会转成数字；bool 字段是 True/False。
    #         界面上留空的字段可能不存在于 dict 中，取值务必用 config.get("key")。
    ...
    return {
        "success": True,                # 必填: 签到是否成功(布尔)
        "message": "签到成功, 获得 10 积分",  # 必填: 一句话结果, 展示在任务列表
        "data": {"points": 10},         # 可选: 附加信息
    }
```

**`data.expires_info` —— 凭证有效期上报（可选，推荐）**：
凭证类渠道（Cookie/Token/JWT）若能从凭证中解析出过期时间，建议在 `data` 中带上
`expires_info` 数组，平台会存入任务并在「任务管理」列表的**令牌有效期**列展示，
按剩余天数着色（<7 天红 / <30 天黄 / 其余绿），到期前一目了然：

```python
"data": {
    "expires_info": [
        {"label": "主号", "expires_at": "2026-11-22 02:06:22"},  # label=账号备注, expires_at=本地时间字符串
    ]
}
```

说明：仅在有值时更新（某次运行失败不会清空历史记录）；无法解析过期时间的渠道可不带此字段。

**`data.balance_info` —— 剩余积分上报（可选，推荐）**：
`data.balance_info` 数组，平台会存入任务并在「任务管理」列表的**剩余积分**列展示，
每次运行后自动刷新，签到奖励/积分变动一眼可见：

```python
"data": {
    "balance_info": [
        {"label": "主号", "value": 498},          # label=账号备注或积分名称, value=当前余额
    ]
}
```

说明：同样仅在有值时更新；积分余额无法获取的渠道可不带此字段。

硬性要求：

1. **必须返回 dict**，且含 `success`(bool) 与 `message`(str)。不要返回 None、字符串，也不要只打印不返回。
2. **不要抛异常到最外层**。所有可预期错误(网络失败、登录失效、解析失败)都应捕获后
   返回 `{"success": False, "message": "..."}`。未捕获异常虽然会被引导代码兜底，
   但用户只能看到裸异常信息，体验差。
3. **进度/细节用 `print()` 输出**（脚本里 `print` 即可，平台捕获 stdout）。
   不要打印以 `__CHECKIN_RESULT__` 开头的内容，那是平台保留的结果行前缀。
4. **结果判定要真实**：接口返回"今日已签到"属于成功（幂等命中）；登录失效、参数错误属于失败。
   不要为了"日志好看"把失败包装成成功。
5. **遵守目标站点的频率礼貌**：控制请求次数、设置合理超时、失败重试不超过 3 次、
   重试加退避(如 2s/4s/8s)。
6. **不要硬编码任何个人凭证**。所有账号信息必须通过 config 传入。

### 4.3 文件末尾的引导代码（不要修改）

```python
if __name__ == "__main__":
    import json as _json
    import sys as _sys
    try:
        _config = _json.loads(_sys.stdin.read() or "{}")
    except Exception:
        _config = {}
    try:
        _result = run(_config)
        if not isinstance(_result, dict):
            _result = {"success": False, "message": "run() 未返回字典"}
    except Exception as _exc:
        _result = {"success": False, "message": "脚本异常: %s" % _exc}
    print("__CHECKIN_RESULT__" + _json.dumps(_result, ensure_ascii=False))
```

它的职责：从 stdin 读配置 → 调用 `run()` → 兜底异常 → 打印结果行。
`channels/_template/channel.py` 与 `channels/workbuddy/channel.py` 都是标准范例。

### 4.4 README.md —— 人工配置获取指南（面向不会看代码的用户，必须提供）

config_schema 里的每个字段，普通用户往往不知道"上哪获取"。渠道目录下的 `README.md`
就是写给**人工用户**的指南，平台会读取它并在界面三处展示：
「配置指南」页(左侧导航, 汇总全部渠道教程与通用凭证说明)、「渠道管理」页的
**📖 配置获取指南** 按钮，以及「新建/编辑任务」弹窗里的 **"如何获取这些信息?"** 链接。

写作要求（以 `channels/workbuddy/README.md` 为标准范例）：

1. **逐个配置项说明获取方法**：去哪个网站/哪个文件、点什么菜单、复制哪个字段。
   涉及本机路径时分操作系统写全（Windows `%...%` / macOS `~/...`）。
2. **可复制**：给出字段样例(长什么样、什么前缀、多长)与填写格式示例。
3. **有前提条件**：如"必须先在这台电脑登录过客户端""需要管理员权限"等。
4. **常见问题**：列出凭证失效、路径找不到等高频问题的现象与处理。
5. 用平台支持的轻量 Markdown（标题 `#`/`##`/`###`、列表 `-`、表格、加粗 `**`、行内代码反引号）。
   不要放图片、引用块、代码块围栏等其余语法。
6. 凭证获取步骤**不要**引导用户把凭证发给任何人或粘贴到不可信的工具里。

从 `channels/_template/README.md` 的骨架开始写。

## 5. 开发步骤（Agent 按此逐步执行）

1. **读模板**：完整阅读 `channels/_template/channel.py`。
2. **复制目录**：`cp -r channels/_template channels/<渠道id>`（Windows 用 `xcopy` 或手动创建）。
3. **写 META**：按 4.1 声明渠道信息与配置字段。先想清楚用户需要填什么
   （Cookie？账号密码？账号列表？），凭证一律 `password`/`textarea`。
4. **实现 run(config)**：按 4.2 的要求写签到逻辑。典型结构：
   - 解析/校验配置 →
   - 登录或携带凭证请求签到接口 →
   - 解析响应，区分「成功 / 已签到(算成功) / 未登录(失败) / 其他失败」→
   - `print` 过程日志 → 返回结果 dict。
5. **本地测试**（必须做，不要只靠界面）：

   ```bash
   # 成功路径(把 key/value 换成你声明的配置字段)
   echo '{"cookie": "测试值"}' | python channels/<渠道id>/channel.py

   # Windows PowerShell
   '{"cookie": "测试值"}' | python channels/<渠道id>/channel.py
   ```

   **验收标准**：输出最后一行是 `__CHECKIN_RESULT__{"success": ..., "message": ...}`；
   人为制造错误配置(如错误 Cookie)时，`success` 应为 `false` 且 message 能说明原因。
6. **平台内验证**：启动平台(`python app.py`)，打开「渠道管理」页：
   - 渠道卡片出现且标记「正常」（若显示"加载失败"并附错误信息，说明 META/run 有问题，先修复）；
   - 「新建任务」时该渠道的配置表单字段与 config_schema 一致；
   - 创建任务(可把定时规则先设为不影响真实签到的值)→ 点「▶ 立即运行」→
     在「执行日志」查看输出与结果，确认状态与消息符合预期。
7. **收尾**：按 4.4 编写渠道目录的 `README.md`(配置获取指南)；渠道用到第三方库时更新根目录
   `requirements.txt`。

## 6. 编码与安全要求

- **Python 版本**：兼容 3.9+；优先用标准库(`urllib.request` 完全够用)，需要会话/重试时用 `requests`。
- **编码**：文件头加 `# -*- coding: utf-8 -*-`；所有 print 中文正常（平台已设置 UTF-8 环境）；
  平台为 Windows 注入了 `-X utf8` 与 `PYTHONIOENCODING=utf-8`，无需自行处理 GBK 问题。
- **网络请求**：一律设置超时(建议连接/读 15~25 秒)；不要无限重试；不要并发轰炸目标站点。
- **凭证安全**：日志中**不要完整打印** Cookie/Token/密码(可打印前 8 位 + `...`)；
  异常信息里可能带 URL 参数，注意脱敏。
- **幂等性**：签到接口重复调用应当安全(大多数平台"今日已签到"即幂等)；
  若接口不幂等，在 `run()` 里自行做"今日已签"标记(如渠道目录下写状态文件)。
- **多账号**：若渠道支持多账号，约定用 textarea 每行一个账号（格式自定并在 help 中写清），
  逐个执行并在日志中按账号标注结果；整体 `success` = 全部账号成功。

## 7. 验收清单（Agent 提交前逐项自检）

- [ ] 目录名合法（小写/数字/下划线，不与现有渠道重名），入口文件名为 `channel.py`
- [ ] `META` 含 `name`；`config_schema` 每项都有 `key`/`label`；凭证字段用 `password`
- [ ] 渠道目录含 `README.md` 配置获取指南，覆盖 config_schema 中每个字段的获取方法
- [ ] `run(config)` 各种情况都返回 dict（成功/已签到/未登录/网络失败/配置缺失）
- [ ] 本地 `echo '{...}' | python channel.py` 输出含 `__CHECKIN_RESULT__` 结果行
- [ ] 错误配置下 `success=false` 且 message 可读，进程退出码无要求但脚本不挂起
- [ ] 全程无硬编码凭证；日志无敏感信息明文
- [ ] Web「渠道管理」页渠道显示「正常」；新建任务表单字段正确
- [ ] 手动运行一次，日志输出完整、状态正确
- [ ] 第三方依赖已加入 `requirements.txt`
- [ ] 平台通用代码（`core/`、`api/`、`web/`）**零改动**

## 8. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 渠道页显示"加载失败: channel.py 缺少 META" | META 没定义/拼写错误 | 检查 `META = {...}` 是否在模块顶层 |
| 新渠道没出现在渠道列表 | 目录以 `_` 开头，或文件名不是 `channel.py` | 改目录名/文件名 |
| 界面表单出现未知字段 | config_schema 里 type 写错(会被降级为 text) | 用规范中的六个类型之一 |
| 任务一直"运行中"直到超时 | 脚本内部死等(如 input()、无超时的请求) | 去掉交互输入，网络请求加 timeout |
| 日志出现结果但状态是失败 | 打印了 `__CHECKIN_RESULT__` 前缀但 JSON 不合法 | 只在引导代码打印结果行 |
| 本地测试正常、平台里失败 | 平台以渠道目录为 cwd 执行，且配置来自表单 | 不要依赖调用方的 cwd；用 config.get 取值并校验 |
| 中文乱码(极少数终端) | 手动运行时终端不是 UTF-8 | 用 `python -X utf8 channel.py` 测试 |
